## Contract

```ts
// packages/core/src/cad/check.ts (kernel-free)
export interface CadCheckReport { readonly pageId: PageId; readonly features: number;
  readonly entities: number; readonly errors: readonly { id: ElementId; code: string }[];
  readonly bounds: { min: Vec3; max: Vec3 } | null } // bounds of tool solids, not of the final solid
export function checkCadPage(elements: readonly Element[], pageId: PageId): CadCheckReport;
// packages/core/src/cad/testing/generate.ts
export function generateCadDocument(options: { features: number; entitiesPerSketch: number }): Document;
// ids come from newElementId (26-character ULIDs) driven by a seeded generator, so sizes are realistic and runs repeatable
```

`nodetto-cli cad check <file> [--page <id>] [--json]`

## Behavior

- `checkCadPage`: `analyzeCadPage` statuses plus, for each extrude,
  `buildLoops` (profile errors) and the bounds of its prism vertices. It
  does not triangulate caps and does not call a kernel. Linear passes,
  flat arrays, no recursion.
- Command (synchronous, dispatch switch in `apps/cli/src/commands.ts`):
  checks every `cad3d` page or the one named; text output one line per
  page (`<page name>: <n> features, <m> entities, <k> errors`) followed by
  one line per error (`<short id> <code>`), `--json` prints the reports.
  Exit 0 without errors, 1 with errors, 2 for usage errors or when the
  document has no CAD page. `COMMAND_HELP.cad` documents usage, the status
  codes, the content rule and that geometry is regenerated by the app; the
  MCP tool `nodetto_cad` appears through the existing derivation.
- Help: `edit` help gains a short CAD section with one self-authored
  example batch (create a page of kind `cad3d`, a sketch, a rectangle as
  four lines, an extrude) and the two rule error codes.
- `arrange` and `lint` treat `cad3d` like `pcb` (unsupported page kind,
  same exit code and message form). `types` lists the CAD types and the
  page kind's typical types.
- No CLI code path imports `@nodetto/cad-kernel` or `manifold-3d`; the
  engine bundle build (`apps/cli/scripts/build-engine.ts`) must stay free
  of WebAssembly (assert by grepping the built bundle in the native test).

## Tests

- `check.test.ts`: clean Plate; each error class; bounds of the Plate tool
  solids; 20,000 elements under 1,000 ms in Bun.
- `cad-command.test.ts`: text and JSON output, exit codes 0, 1, 2,
  `--page` selection, against `cad-bracket.jsonl`.
- `cad-enforcement.test.ts` through the `edit` command: `add` of a
  `shape.geo` on the CAD page fails naming `page.contentKind` and writes
  nothing; `add` of `cad.line` on a freeform page fails the same way;
  `set-page-kind` (or the op that updates `pageKind`) to and from `cad3d`
  fails with `page.kindLocked`; `add` of a `design.token` on the CAD page
  succeeds (resource carrier); deleting a sketch through `delete` leaves a
  document that passes `validate` and whose `cad check` reports
  `cad.reference.missing` for the extrude; `add-page` with kind `cad3d` succeeds; the
  help example batch runs and the result passes `validate` and
  `cad check`; `convert` of a CAD element fails; copy-shapes between a CAD
  and a 2D page fails; `arrange` and `lint` exit like PCB.
- `mcp.test.ts` and `mcp-stdio.test.ts` pass unmodified (derived lists).
- `native-parity/cad.test.ts` (runs when `NODETTO_CLI_TEST_BINARY` is
  set, like the other parity files): byte parity of `cad check`,
  `validate` and one `edit` batch between Bun and the binary;
  `generateCadDocument({features: 500, entitiesPerSketch: 19})` (10,000
  records) passes `validate` and `cad check` natively in under 10,000 ms
  each; the built engine bundle contains no `WebAssembly` identifier.
